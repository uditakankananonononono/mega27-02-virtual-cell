# BiGG model survey, fixed before outcome extraction

Question: how often do public BiGG metabolic models explicitly demand molybdenum cofactor compounds in their biomass reaction, and how variable are model structure and baseline growth? This tests whether the VC-2 MoCo biomass artifact is a model-specific issue or a widespread candidate failure mode. Use the BiGG v2 public `/api/v2/models` list available on 2026-09-25, then fetch every distinct model ID's JSON snapshot under `/static/models/<ID>.json`. Save each fetched file and its SHA-256; reject a failed fetch or unparsable JSON. Compute reaction/metabolite/gene counts, biomass-objective reaction(s) from objective coefficients, MoCo-like biomass metabolites by case-insensitive `moco|molybdo|bmoco|mobd` names/IDs, COBRApy baseline solver status and growth under its stored bounds. Do not change media, assume shared strain labels, or interpret MoCo presence alone as false essentiality. Count only unique accessioned BiGG model IDs whose snapshots actually fetched and yielded the result row. Do not count archive pages or failed downloads. This is descriptive across heterogeneous organisms, not prospective biological validation. Source-list and model URLs, download SHA-256, computation outcome, and exclusions go in results. No result-dependent exclusions.

Amendment before outcome extraction: full COBRA loading/solving over 108 models exceeded the run window. Keep the preregistered objective census and model-structure checks, but drop the descriptive growth output (record `not_scored`); no claim about growth. Do not change inclusion criteria.

Final raw data storage: model snapshot bytes are kept in private Drive, with SHA-256 per accession in the committed CSV and a deterministic fetch script in git. A source listing that changes later is revalidated against the archived listing hash.
